# 산천어축제 안내 기획문서 (v3, 2026-11-16)

KNU RE:RISE 7팀 · 배포: 웹 https://parking-mate.vercel.app · 서버 https://parkingmate-api.onrender.com (API 명세 `/swagger-ui.html`)

## 1. 한 줄 정의
축제 임시주차장의 **남은 자리**를 입·출구 센서로 세어 보여 주고, **셔틀 도착 시간·예상 위치**와 **축제장 안내 지도**를 함께 제공해서, 방문객이 가까운 주차장에 몰리지 않고 **여유 있는 먼 주차장에 대고 셔틀로 오게** 돕는 서비스.

## 2. 방향이 바뀐 과정
### 2-1. 2026-11-12 교통 담당자 인터뷰 후
| 기존 구상 | 담당자 의견 | 바뀐 방향 |
|---|---|---|
| QR 예약 전용 주차장, 30분 자리 확보 | 현장 차량만으로도 이미 만차라 예약 자리를 비워 둘 수 없음. 고령 방문객이 많아 젊은 층 특혜로 보일 수 있음 | 예약은 하지 않음 |
| 빈자리 기준 자동 배정 | 방문객은 "나 한 대 댈 자리는 있겠지" 하며 가까운 주차장으로 감. 강 건너 부지는 심리적으로 멀게 느낌 | **먼 주차장에 댈 이유**를 줌 |
| 센서로 입·출차 집계 | 지금은 직원이 주차장마다 직접 보고 무전으로 공유. 눈이 오면 주차선이 안 보여 사람이 판단 | 센서 집계 + **직원이 운영 가능 면수·상태를 수정** |

### 2-2. 2026-11-16 팀 결정
- **이용권 발급·QR 기능은 뺌.** 이용권 지급은 화천군(축제 운영) 쪽이 맡는 게 맞다고 판단. 서비스에는 "위라리 둔치에 대고 셔틀을 타면 체험 이용권을 드려요" **안내만** 남김.
- 대신 방문객이 "어디에 대고, 셔틀은 언제 오고, 축제장에서 뭘 할 수 있는지"를 한 번에 알도록 **셔틀 예상 위치·남은 시간**과 **축제장 안내 지도**를 추가.

## 3. 사용자와 화면
### 방문객 (스마트폰)
| 화면 | 주소 | 하는 일 |
|---|---|---|
| 주차장 현황 | `/` | 맨 위 **추천 상자**(남은 자리 많은 곳 1곳 · 셔틀 정류장 · [카카오맵 길찾기]). 여유/혼잡/만차/정보없음 칸을 누르면 그 상태만 보기. 지도·목록에서 주차장을 누르면 화면 아래에 **[카카오맵 길찾기] [자세히]**, 다시 누르면 해제 |
| 주차장 상세 | `/p/{코드}` | 남은 자리, 카카오맵 길찾기, 이용 혜택 안내, **셔틀 정류장 지도 · 주차장에서 걸어서 N분** · 정류장까지 길찾기, 다음 셔틀 N분 후, 타면 축제장까지 N분 |
| 셔틀 | `/shuttle` | 버스 앱처럼 **정류장 한 줄** + 정류장 사이 버스 위치, 정류장마다 "N분 후", 축제장 앞 정류장 표시. 지도는 "지도로 보기" |
| 축제장 안내 | `/festival` | **안내도**(강을 가운데 둔 그림 지도: 얼음 위 낚시터·체험장, 양쪽 둑 접수처·먹거리·안내센터) / 실제 지도 전환. 장소를 누르면 요금·길찾기. 25곳 |

### 현장 직원·담당자 (휴대폰·노트북) `/admin`
- **주차장 탭**: 주차장 지도(지금 차량 수, 5초 갱신, 핀을 누르면 그 주차장 조정 칸으로), 센서 기록(오늘 입차·출차, 입구·출구 연결 상태), 주차장별 차량 수 ±1/±10, 상태(자동·여유·혼잡·만차·운영 안 함), 운영 가능 면수(눈 올 때), 시연 초기화
- **축제장 장소 탭**: 지도를 눌러 장소 추가, 핀을 눌러 수정·위치 이동·삭제

## 4. 셔틀 계산 규칙
- 공식 노선(2026): 화천체육관 → 청소년 수련관 → 화천실버복지센터 → 구 헌병대 → 정보산업고 → 시외버스터미널 → 배수펌프장 → 다시 체육관. 토·일 09:00~18:00, 약 20분 간격, 4대.
- 정류장 사이 시간은 공개되지 않아 **10분으로 추정** → 한 바퀴 70분.
- **버스 위치** = 첫 정류장 출발 시각부터 흐른 시간으로 계산한 **예상 위치**(실시간 GPS 아님). 화면에 그렇게 표시.
- **축제장 앞 정류장** = 축제장 장소(낚시터·체험장 등) 300m 안 정류장: 청소년 수련관·구 헌병대·배수펌프장. "축제장까지 N분" = 탄 정류장에서 처음 만나는 축제장 앞 정류장까지.
- `SHUTTLE_ALWAYS=true`(시연용 기본값): 운행표와 관계없이 매일 0시부터 20분 간격으로 계속 도는 것으로 계산. 실제 운영 시 `false`.

## 5. 인터뷰 기록 (2026-11-12, 녹음 대조)
### 운영 사실 (00:00~14:00)
- 금요일부터 증가, 월요일까지 감소. 화·수·목은 임시주차장 여유, 그 외 60~80% (00:30~01:32)
- 토요일은 8시 30분이면 모든 주차장 만차 (04:29)
- 축제장 양쪽 일방통행 구간 노상주차 운영, 불법주정차 구역은 별도 (01:47, 02:03)
- 강 건너 큰 부지로 유도하려 하나 "강을 건너야 한다는 생각"에 잘 안 감. 진입을 막으면 정체가 길어져 결국 받아들임 (04:50~06:38)
- 셔틀 20분 간격 (06:38). 인력: 올해 90명, 내년 120명, 주차장당 최소 6명, 무전으로 확인 (07:23~09:19). 차량 수는 "사람이 일일이 확인" (08:08)
- 화천초 160면 (09:57). 2027 사용 여부는 녹음상 불명확 → 확인 필요
- 이용권: "눈썰매나 이런 프로그램들, 낚시는 제외하고… 두 번 탈 수 있는 정도" (10:20~11:05)

### 후반 (14:00~22:30)
- 예약 주차장이 안 되는 이유: "주차 예약을 한다고 하면 이거를 비워놓는 상황이 생기잖아요" (15:11)
- 고령층: "QR 주차장은 젊은 층에 대한 특혜라고 생각이 들어요" (16:40)
- 담당자 제안: 먼 주차장 이용자에게 무료이용권 (16:58~18:24)
- 셔틀: 이용객이 많으면 3~5대로 증차 생각 (18:26)
- 자료: 교통계획은 담당자 보유, 일방통행·셔틀은 재단법인 나라 홈페이지. "멘토링 할 때 따로 공개" (19:14~19:38)
- 500대: 녹음에 없음 → 팀 통화 필기 값

### 현장 고충 (20:13~21:32)
- 교통 통제 권한은 경찰에 있고, 일자리 근로자는 민간인이라 권한이 없음. 통제 중 사고가 나면 통제한 사람 책임 → 부담이 큼
- 이 서비스와의 연결: 막아서 돌려보내는 대신 **정보와 혜택으로 스스로 분산**하게 해 통제 부담을 줄이는 방향 (기대효과, 미측정)

## 7. 시스템 구성
```
[입구 적외선 A·B] → STM32 ─USB─┐
                               ├→ 노트북 브리지(sensor/bridge.py) ─HTTPS JSON→ Spring Boot API ─ PostgreSQL(Neon)
[출구 적외선 A·B] → Pico 2 WH ─Wi-Fi─┘                                    ↑
                                              React 웹(방문객·현장 관리, Vercel) ┘
```
- 프론트 React + Vite → Vercel / 백엔드 Spring Boot 4 (Java 21) → Render(Docker) / DB PostgreSQL → Neon
- 지도: 카카오맵(JavaScript 키, 도메인 등록 필요), 실패 시 OpenStreetMap
- main 에 push 하면 Vercel·Render 자동 배포. Render 무료 서버는 15분 미사용 시 잠듦(첫 접속 약 1분)

## 9. API
| 도메인 | 메서드·경로 | 설명 | 인증 |
|---|---|---|---|
| 주차장 | GET /api/lots | 전체 목록 + 남은 자리·혼잡도·센서 상태 | - |
| | GET /api/lots/{code} | 한 곳 상세 | - |
| | PATCH /api/admin/lots/{code} | 차량 수(currentCount/delta)·운영 가능 면수·상태 수정 | 관리자 |
| 센서 | POST /api/sensor/events | 입·출차 이벤트 묶음. 같은 deviceId+seq 는 한 번만 | 센서 |
| | POST /api/sensor/heartbeat | 이벤트 없이 연결 신호 | 센서 |
| | GET /api/admin/lots/{code}/events | 최근 센서 기록 | 관리자 |
| | GET /api/admin/lots/{code}/sensors | 입구·출구 장치별 연결 상태 | 관리자 |
| | GET /api/admin/summary | 오늘 입차·출차 수 | 관리자 |
| 셔틀 | GET /api/shuttle | 노선·정류장(다음 출발, N분 후, 축제장까지 N분)·버스 예상 위치 | - |
| 축제장 | GET /api/places | 축제장 장소 목록 | - |
| | POST /api/admin/places | 장소 추가 | 관리자 |
| | PATCH /api/admin/places/{id} | 장소 수정·위치 이동 | 관리자 |
| | DELETE /api/admin/places/{id} | 장소 삭제 | 관리자 |
| 공통 | GET /api/now | 서버 기준 시각(시연 시계 반영) | - |
| | POST /api/admin/demo/reset | 시연 초기화: 센서 기록 삭제, 위라리 차량 수 188대로 | 관리자 |

인증: 관리자 `X-Admin-Key`(`ADMIN_OPEN=true`면 생략), 센서 `X-Sensor-Key`(항상 필요). 값은 환경 변수에만 둔다.

## 10. 발표에서 구분할 것
- **구현·시연**: 주차장 현황·추천·길찾기, 센서 → 남은 자리 반영, 셔틀 예상 위치·N분 후, 축제장 안내 지도, 현장 관리(차량 수·면수·상태·장소)
- **가정·예시**: 일부 주차장 위치(근사), 면수 대부분(정보없음), 정류장별 시각(10분 추정), 버스 위치(시간표 계산)
- **기대효과(미측정)**: 먼 주차장 이용 증가, 가까운 주차장 진입 감소, 직원 무전 확인 업무 감소

## 11. 남은 확인 사항 (멘토링 때 담당자에게)
1. 각 임시주차장의 정확한 위치와 면수, 2027 축제 사용 여부(특히 화천초)
2. "강 건너 약 500대" 부지가 위라리 둔치인지
3. 이용권 지급 방식·장소(화천군 운영)와 대상 주차장
4. 정류장별 실제 도착 시각, 증차 계획
