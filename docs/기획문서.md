# 화천 Parking Mate 기획문서 (v2, 2026-11-15)

## 1. 한 줄 정의
축제 주차장의 **남은 자리**를 실시간으로 보여 주고, **먼 임시주차장에 주차한 방문객에게 무료이용권**을 주어 스스로 분산 주차하게 만드는 서비스.

## 2. 방향이 바뀐 이유 (2026-11-12 교통 담당자 인터뷰)
| 기존 구상 | 담당자 의견 | 바뀐 방향 |
|---|---|---|
| QR 예약 전용 주차장, 30분 자리 확보 | 현장 차량만으로도 이미 만차라 예약 자리를 비워 둘 수 없음. 고령 방문객이 많아 젊은 층 특혜로 보일 수 있음 | 예약은 하지 않음 |
| 빈자리 기준 자동 배정 | 방문객은 "나 한 대 댈 자리는 있겠지" 하며 가까운 주차장으로 감. 강 건너 부지는 심리적으로 멀게 느낌 | **먼 주차장에 댈 이유(혜택)**를 줌 |
| 센서로 입·출차 집계 | 지금은 직원이 주차장마다 직접 보고 공유함. 눈이 오면 주차선이 안 보여 사람이 판단해야 함 | 센서 집계 + **관리자가 운영 가능 면수와 상태를 수정** |
| — | 먼 주차장 이용자에게 무료이용권을 주는 방안을 검토 중. 확인과 발급 과정을 편하게 해 주면 좋겠음 | **실물 QR → 주차 확인 → 이용권 발급·사용 처리** |

## 3. 사용자와 화면
### 방문객 (스마트폰)
1. **지도 홈 `/`**: 모든 임시주차장, 남은 자리 또는 혼잡 상태, 셔틀 정류장 표시. 혜택 주차장 강조. 카카오맵 길찾기.
2. **주차장 QR 화면 `/p/{주차장코드}`**: 주차장 입구 안내판의 실물 QR을 찍으면 열림. 이 주차장의 남은 자리, 가장 가까운 셔틀 다음 출발 시각, **무료이용권 받기**(차량번호 입력).
3. **이용권 화면 `/v/{이용권코드}`**: 축제장 안내소에서 보여 줄 큰 코드와 QR.
4. **셔틀 시간표 `/shuttle`**.

### 현장 직원·담당자 (노트북·휴대폰)
5. **관리 화면 `/admin`**: 주차장별 차량 수 +/− 수정, 운영 가능 면수(눈 올 때), 상태(여유·혼잡·만차·운영중지) 지정. 이용권 확인·사용 처리. **스마트폰을 못 쓰는 방문객 대리 발급**.

## 4. 이용권 발급 규칙 (부정 발급 방지)
- 혜택 대상 주차장에서만 발급. 담당자가 말한 대상은 **강 건너 화천대교 쪽 큰 부지(위라리 둔치로 추정)** 뿐 (녹음 10:10, 17:13~18:24). 실버복지센터·구 헌병대는 팀 확대 후보로만 기록(이용권 꺼 둠).
- **차량번호 1대당 하루 1장**.
- 센서가 설치된 주차장은 **최근 90분 안에 센서가 기록한 입차 1건과 이용권 1장을 짝지음**. 입차 기록이 남아 있지 않으면 발급하지 않고 직원에게 안내함. 집에서 QR 사진만 찍어서 받는 것을 막고, 실제로 들어온 차보다 많이 발급되지 않음.
- 직원 대리 발급은 센서 짝이 없어도 가능하며 기록에 "직원 발급"으로 남김.
- 이용권 종류는 **검토 중**. 녹음 10:20~11:05: "눈썰매나 이런 프로그램들, 낚시는 제외하고, 기타 놀거리들, 두 번 탈 수 있는 정도". 화면에는 "체험 프로그램 무료이용권 · 눈썰매 등 2회(낚시 제외)" + "검토 중" 표시.

### 녹음에서 확인된 운영 사실 (2026-11-12, 00:00~14:00)
- 금요일부터 증가, 월요일까지 감소. 화·수·목은 임시주차장 여유, 그 외 60~80% (00:30~01:32)
- 토요일은 8시 30분이면 모든 주차장 만차 (04:29)
- 축제장 양쪽 일방통행 구간 노상주차 운영, 불법주정차 구역은 별도 (01:47, 02:03)
- 강 건너 큰 부지로 유도하려 하나 "강을 건너야 한다는 생각"에 잘 안 감. 진입을 막으면 정체가 길어져 결국 받아들임 (04:50~06:38)
- 셔틀 20분 간격 (06:38). 인력: 올해 90명, 내년 120명, 주차장당 최소 6명, 무전으로 확인 (07:23~09:19). 차량 수는 "사람이 일일이 확인" (08:08)
- 화천초 160면 (09:57). 2027 사용 여부는 녹음상 불명확 → 확인 필요

### 녹음 후반 (14:00~22:30)
- **예약 주차장이 안 되는 이유**: "예약 낚시터분들도 5시에 오고 현장 낚시터분들도 5시에 와요… 주차 예약을 한다고 하면 이거를 비워놓는 상황이 생기잖아요" (15:11)
- **고령층**: "키오스크를 어려워하시는 분들이 굉장히 많으신데… QR 주차장은 젊은 층에 대한 특혜라고 생각이 들어요" (15:11~16:40)
- **담당자가 제안한 흐름 = 지금 구현**: "무료이용권을 주는 주차장에 적용을 하면, 차라리 QR로 하면 내가 이 주차장에 대겠다고 하는" (16:58) → "주차를 한 게 확인이 되면 무료이용권을 발급하고 핸드폰으로 발송을 하듯, 아니면 직접 컴퓨터를 가져와서 연동을 해서" (17:15~17:56)
  - 우리 구현: QR → 센서 입차 확인 → 휴대폰 이용권(본인 발급) / 현장 노트북 관리 화면(직원 발급)
- **셔틀**: 이용객이 많으면 "3대에서 5대까지 증차할 생각" (18:26). 공식 안내는 4대 → 시드는 공식값 4대 유지
- **자료**: 교통계획은 담당자 보유, 일방통행·셔틀은 재단법인 나라 홈페이지 (19:14). "멘토링 할 때 따로 공개" — **멘토링 때 공유 약속, 아직 받지 않음** (19:38)
- **500대**: 녹음에 없음 → 팀 통화 필기 값으로만 기록

### 현장 고충 (발표·문서용, 20:13~21:32)
- 교통 통제 권한은 경찰에 있고, 일자리 근로자는 민간인이라 권한이 없음
- 조례로는 법을 넘을 수 없어 법적 제도가 있으면 안전하게 보장받을 것 같다는 의견
- 통제 중 사고가 나면 통제한 사람 책임 → 부담이 큼. 지역 자체가 고령화
- 이 서비스와의 연결: 강제 통제 대신 **혜택으로 스스로 분산**하게 하는 방식이라 현장 인력의 통제 부담을 줄이는 방향 (기대효과, 미측정)

## 5. 데이터 출처 원칙
| 데이터 | 출처 | 상태 |
|---|---|---|
| 임시주차장 11개소 + 캠핑카 1개소 이름 | 재단법인 나라 2026 축제 「임시 주차장 안내」 배치도 | 공식(2026) — 2027 업데이트 예정 |
| 주말 셔틀 노선·시간 | 같은 사이트 「축제장 외부 주말 셔틀」: 토·일 09:00~18:00, 4대 순환, 약 20분 간격 | 공식(2026) |
| 좌표 | OpenStreetMap 건물 위치. 없는 곳은 공식 배치도에서 **근사(±150m)** | 카카오 로컬 API로 보정 예정 |
| 정류장별 도착 시각(수정) | 정류장 간 10분으로 추정 (4대·20분 간격 순환 기준) | 추정 |
| 수용 면수 | 화천초 160면(녹음 09:57), 강 건너 부지 약 500대(팀 통화 필기) | 나머지는 **미확인** → "정보없음" 표시 |
| 이용권 종류·수량 | 녹음 10:20: 눈썰매 등 2회, 낚시 제외 — 담당자 검토 중 | 검토 중 |

화면과 데이터에는 출처 상태를 함께 저장하고, 추정값을 공식값처럼 보여 주지 않는다.

## 6. 시스템 구성
```
[입구 적외선 A·B] → STM32 ─USB─┐
                               ├→ 노트북 브리지(sensor/bridge.py) ─HTTPS JSON→ Spring Boot API ─ PostgreSQL
[출구 적외선 A·B] → Pico 2 WH ─Wi-Fi(HTTP)─┘                              ↑
                                                         React 웹(방문객·관리자) ─┘
```
- 프론트: React + Vite → **Vercel**
- 백엔드: Spring Boot 4 (Java 21) → **Render** 무료 웹 서비스(Docker). 15분 동안 요청이 없으면 잠들고 깨는 데 약 1분 걸림 → 시연 전에 미리 깨워 두기.
- DB: PostgreSQL → **Neon** 무료. 로컬 개발은 H2(PostgreSQL 모드)로 DB 설치 없이 실행.
- 대안: 시연장 인터넷이 불안하면 노트북에서 백엔드를 직접 실행.

## 7. ERD
```
parking_lot 1──N sensor_device 1──N vehicle_event N──0..1 voucher
parking_lot 1──N voucher N──1 benefit
shuttle_route 1──N shuttle_stop N──0..1 parking_lot
```
| 테이블 | 주요 컬럼 |
|---|---|
| parking_lot | id, code(UK, QR 주소), name, category, lat, lng, coord_source, capacity, capacity_source, operable_capacity, current_count, manual_status, incentive, sensor_enabled, shuttle_stop, note, data_source, updated_at, version |
| sensor_device | id, device_id(UK), lot_id(FK), gate(ENTRY/EXIT), last_seq, last_seen_at |
| vehicle_event | id, device_id, lot_id(FK), direction(IN/OUT), seq, occurred_at, received_at, voucher_id(FK, 짝지은 이용권) · UK(device_id, seq) |
| benefit | id, name, description, active, is_example |
| voucher | id, code(UK), lot_id, benefit_id, plate_number, festival_date, channel(SELF/STAFF), status(ISSUED/REDEEMED/VOID), issued_at, redeemed_at · UK(plate_number, festival_date) |
| shuttle_route | id, name, days, first_departure, last_departure, interval_minutes, bus_count, source |
| shuttle_stop | id, route_id, seq, name, lat, lng, offset_minutes, offset_source, lot_id |

## 8. 도메인별 API
| 도메인 | 메서드·경로 | 설명 |
|---|---|---|
| 주차장 | GET /api/lots | 전체 목록 + 남은 자리·혼잡도 |
| | GET /api/lots/{code} | 한 곳 상세 |
| | PATCH /api/admin/lots/{code} | 차량 수·운영 가능 면수·상태 수정 (관리자) |
| 센서 | POST /api/sensor/events | 입·출차 이벤트 1건 또는 묶음 (센서 키) |
| | GET /api/admin/lots/{code}/events | 최근 이벤트 (관리자) |
| 셔틀 | GET /api/shuttle | 노선·정류장·다음 출발 시각 |
| 혜택 | GET /api/benefits | 이용권 종류 |
| 이용권 | POST /api/vouchers | 방문객 발급 |
| | GET /api/vouchers/{code} | 이용권 조회 |
| | POST /api/admin/vouchers | 직원 대리 발급 |
| | POST /api/admin/vouchers/{code}/redeem | 사용 처리 |
| | GET /api/admin/summary | 오늘 발급·사용·입출차 합계 |

인증: 관리자 `X-Admin-Key`, 센서 `X-Sensor-Key` (환경 변수, 저장소에 올리지 않음).

### 센서 JSON
```json
POST /api/sensor/events
{ "events": [ { "deviceId": "entry-stm32", "seq": 41, "direction": "IN", "occurredAt": "2027-01-16T09:12:03+09:00" } ] }
```
같은 `deviceId + seq`는 한 번만 반영된다(재전송 안전).

## 9. 발표에서 구분할 것
- **구현·시연**: 웹 지도, QR 화면, 이용권 발급·사용, 관리자 수정, 센서 → 남은 자리 반영
- **가정·예시**: 주차장 위치 일부, 면수 대부분, 정류장별 시각, 이용권 종류, 혜택 대상 주차장
- **기대효과(미측정)**: 먼 주차장 이용 증가, 직원 확인·발급 업무 감소

## 10. 남은 확인 사항 (멘토링 때 담당자에게)
1. 각 임시주차장의 정확한 위치와 면수, 2027 축제 사용 여부
2. "강 건너 약 500대" 부지가 위라리 둔치인지
3. 이용권 종류·수량·조건과 혜택 대상 주차장
4. 주차 확인과 이용권 사용 처리를 맡을 인력과 장소
