# 발표·시연 계획 (11/21 토, 발표 7분 + 질의 3분, 20쪽) — 2026-11-16 최신

듣는 사람: 화천군청 멘토(교통 담당 포함). 이 프로젝트를 **처음 듣는다** → 1학기 내용부터 짧게.
핵심 한 줄: **"가까운 주차장을 더 만들 수는 없으니, 여유 있는 먼 주차장으로 가게 만드는 정보를 한 화면에 모았다."**

## 2. 라이브 시연 순서 (1분 20초)
준비물: 노트북(브리지), 센서 키트(입구 A·B), 시연용 휴대폰(미러링), 프로젝터에 노트북 화면.
서버: Render 환경 변수 `DEMO_CLOCK=2027-01-16T09:30`(축제 토요일 오전), `SHUTTLE_ALWAYS=true`.

1. (15초) 휴대폰 홈: **추천 상자** "위라리 둔치 312자리 남음 · 셔틀 정류장: 화천체육관" → **[카카오맵 길찾기]** 눌러 앱이 열리는 것까지
2. (20초) 발표장 **화천평생학습관 주차장 남은 자리 50** → 입구 센서를 판으로 A→B 가리기 → **49** → 출구 센서 가리기 → **50** ("직원이 무전으로 세던 걸 센서가 셉니다")
3. (20초) 위라리 상세: **셔틀 정류장 지도 · 걸어서 약 3분 · 다음 셔틀 N분 후 · 타면 축제장까지 10분**
4. (20초) 셔틀 탭: 정류장 한 줄에서 **버스가 어디쯤 있는지**
5. (15초) 축제장 탭: **안내도**에서 현장낚시터 눌러 요금·길찾기

### 플랜 B
- 센서 안 되면: `python sensor/simulate.py --api https://parkingmate-api.onrender.com --key "SENSOR_KEY" --count 3 --fast`
- 인터넷 안 되면: 노트북 로컬 실행 (README "로컬 실행")
- 최악: 미리 찍은 시연 영상 → [시연영상_촬영계획.md](시연영상_촬영계획.md) (노션 「시연 영상 촬영 계획」)

## 3. 예상 질문과 답 (3분)
| 질문 | 답의 요지 |
|---|---|
| 셔틀 위치는 진짜인가? | 지금은 시간표로 계산한 예상 위치라고 화면에 적어 뒀습니다. 기사님 휴대폰 위치를 보내면 실제 위치로 바꿀 수 있게 구조를 나눠 뒀습니다. |
| 이용권은 누가 주나? | 지급은 화천군(축제 운영)이 맡고, 저희는 "먼 주차장에 대면 이용권" 안내로 방문객을 유도합니다. 인터뷰에서 담당자께서 제안하신 방향입니다. |
| 어르신들은 휴대폰을 잘 못 쓰시는데? | 첫 화면에 추천 1곳과 큰 길찾기 버튼만 보이게 했고, 글자 19px 이상·버튼 52px 이상입니다. 현장 직원 화면은 주차 안내에 그대로 쓰실 수 있습니다. |
| 눈 오면 주차선이 안 보이는데? | 센서는 들어오고 나간 대수만 셉니다. 실제 댈 수 있는 면수는 직원이 "운영 가능 면수"로 바로 고칩니다(인터뷰 반영). |
| 면수·위치가 정확한가? | 화천초 160면(인터뷰), 위라리 약 500대(통화 메모) 외에는 "정보없음"으로 표시합니다. 좌표 일부는 공식 배치도 근사라 멘토링 때 받는 자료로 고칠 예정입니다. |
| 겨울 추위에 장비·건전지는? | AA 건전지 + 퓨즈 구성. 영하 시험은 아직 못 했고 실제 설치 전 확인할 항목입니다. |
| 설치비·운영비는? | 시제품 부품 약 56만 원(차로 2개). 서버는 무료 등급으로 운영 중이고 실제 운영 비용은 따로 계산이 필요합니다. |
| 기존 방식보다 뭐가 나은가? | 직원은 무전 대신 화면 하나로 같은 숫자를 보고, 방문객은 같은 숫자를 휴대폰으로 봅니다. 입차 기록이 남아 효과를 숫자로 볼 수 있습니다. |
