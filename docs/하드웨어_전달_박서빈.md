# 센서 키트 작업 안내 (박서빈 담당) — 2026-11-15

마감: **11/17(화)** 까지 입구(STM32)·출구(Pico) 센서가 차량 통과를 세고, 노트북을 거쳐 웹 현황판의 "위라리 둔치 남은 자리" 숫자가 바뀌는 것까지.
코드 저장소: https://github.com/bbobbi76/ParkingMate (폴더 `sensor/`)

## 1. 전체 흐름
```
[입구 적외선 A·B] → PC817 입력회로 → STM32 NUCLEO-F401RE ──USB 시리얼──┐
                                                                    ├→ 노트북 sensor/bridge.py → 서버 → 웹 현황판
[출구 적외선 A·B] → PC817 입력회로 → Pico 2 WH ──Wi-Fi HTTP POST────┘
```
- 보드가 할 일은 **차 한 대가 완전히 지나가면 한 번 알리는 것**뿐이에요. 번호 붙이기, 재전송, 서버 전송은 노트북 브리지가 해요.
- 방향 판단: 차로마다 A·B 두 줄을 **진행 방향으로 앞뒤**에 둬요(위아래 아님). A가 먼저 끊기고 B가 이어서 끊긴 뒤 둘 다 풀리면 1대예요. 반대 순서(후진)나 A만 잠깐 끊김(사람)은 무시해요.

## 2. 보드 → 노트북 약속 (이것만 맞추면 됨)
| 보드 | 보내는 방법 | 보내는 내용 |
|---|---|---|
| STM32 (입구) | USB 시리얼, **115200bps** | 한 대 통과마다 `IN` + 줄바꿈(`\n`) 한 줄 |
| Pico 2 WH (출구) | Wi-Fi로 `POST http://<노트북IP>:9000/event` | JSON `{"deviceId":"exit-pico","direction":"OUT"}` (또는 본문에 `OUT` 한 단어) |

다른 문자열(디버그 출력 등)을 시리얼로 보내도 브리지가 무시하지만, 가능하면 `IN`만 보내 주세요.

## 3. 펌웨어 (예시 코드 있음, 핀·논리만 확인해서 수정)
### STM32 — `sensor/stm32_entry/stm32_entry.ino`
- 개발 환경: Arduino IDE + **STM32duino** 보드 패키지 (보드 관리자에서 "STM32 MCU based boards" 설치 → 보드: Nucleo-64 → NUCLEO-F401RE). STM32CubeIDE로 짜도 되고, 시리얼 출력 형식만 같으면 돼요.
- 핀: A = **D2**, B = **D3**, 내부 풀업.
- `BROKEN = LOW` : 빔이 끊겼을 때 PC817 출력이 LOW라고 가정. **실제로 측정해서 반대면 `HIGH`로 바꾸기.**
- 디바운스 80ms, A만 끊기고 8초 동안 B가 안 오면 무시.
- 통과마다 보드 LED가 0.15초 켜져요(눈으로 확인용).

### Pico 2 WH — `sensor/pico_exit/main.py` (MicroPython)
- Thonny로 Pico 2 W용 MicroPython 펌웨어 설치 후 `main.py`로 저장.
- 맨 위 4줄 수정: `WIFI_SSID`, `WIFI_PASS`, `BRIDGE`(노트북 IP, `ipconfig`로 확인), 필요하면 `BROKEN`.
- 핀: A = **GP14**, B = **GP15**. 출구라서 차가 **A(주차장 안쪽) → B(바깥쪽)** 순서로 지나가면 `OUT`.
- 전송 중에는 보드 LED가 켜져요. Wi-Fi 끊기면 자동 재접속.

## 4. 노트북에서 받는 법
```bash
pip install pyserial requests
python sensor/bridge.py --api http://127.0.0.1:8787 --key dev-sensor --serial COM5
```
- `COM5` 는 장치 관리자 → 포트(COM & LPT) → "STMicroelectronics STLink Virtual COM Port" 번호로 바꾸기.
- 화면에 `entry-stm32 입차 (seq …)` / `exit-pico 출차` 가 찍히고 `→ 서버 반영 1건` 이 나오면 성공.
- 보드 없이 브리지만 시험: 브리지 창에서 `i` + Enter = 입차, `o` + Enter = 출차.
- 서버(백엔드)·웹은 임규혁이 띄움: 웹 `http://localhost:5173` 현황판에서 위라리 둔치 숫자 변화 확인, 관리 화면 `/admin` 주차장 탭에 "센서 기록"이 실시간으로 쌓여요.
- 노트북과 Pico는 **같은 Wi-Fi**(휴대폰 핫스팟 추천). 윈도우 방화벽이 9000 포트를 막으면 "허용" 눌러 주세요.

## 5. 배선·전원 확인 순서 (기존 설계 기준)
1. 멀티미터로 AA 10셀 팩 전압(약 15V)과 극성 확인 → 퓨즈 1A 장착.
2. 강압 모듈 출력 5V 확인 (부하 연결 전·후 둘 다).
3. 센서 1쌍 + 입력회로 1채널만 먼저: 빔 가렸다 풀 때 보드 핀 전압이 3.3V ↔ 0V로 바뀌는지 측정 → 이걸로 `BROKEN` 값 결정.
4. A·B 2채널 → 손이나 판으로 A→B 순서로 가려서 시리얼 모니터에 `IN` 한 줄 나오는지.
5. 브리지 연결 → 웹 숫자 변화 확인.
6. 출구 Pico 같은 순서.
- 센서 팩 전압을 GPIO·5V 핀에 **직접 넣지 않기**. 반드시 PC817 입력회로를 거쳐요.
